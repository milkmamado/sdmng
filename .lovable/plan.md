# 최종 전수검사 계획

## 목표
코드는 변경하지 않고 현재 성동점 CRM의 화면, 데이터 조회, 권한, 집계 정의, 매뉴얼을 전수검사해 항목별로 `정상 / 주의 / 수정필요` 판정을 보고합니다.

## 검사 범위
1. **기본 안정성**
   - `tsgo` 타입검사 실행
   - 최신 자동 빌드 결과 확인
   - 실행·콘솔·네트워크 오류 기록 확인

2. **로그인 화면 점검**
   - 현재 검사 환경은 로그아웃 상태이므로, 인증 사용자 목록에서 `torogrr` 마스터 계정을 확인한 뒤 테스트 세션을 발급합니다.
   - 초진관리, 관리환자 리스트와 환자 상세 패키지 영역, 9월 일별 현황과 환자 상세, 이탈 환자 스케줄, 이탈 리스크, 면책환자, 9월 통계 전체·실장별, 사용자 메뉴얼, CRM 연동, 진단·병원 목록 관리, 미분류 환자, 입원/외래매출 관리를 실제 화면에서 엽니다.
   - 각 화면의 콘솔 오류와 4xx/5xx 요청을 수집합니다. 내부망 CRM 자체 호출은 실행할 수 없으므로 브리지 코드를 정적으로 검증합니다.

3. **정적 코드 전수검사**
   - 숨김 대상 버튼·메뉴가 다른 화면에 남았는지와 숨겨진 기능 함수가 보존됐는지 확인
   - 삭제된 `Index.tsx`, `Auth.tsx`의 잔여 참조 확인
   - `daily_patient_status`, `package_transactions`, `patients` 다건 조회를 전부 분류해 페이지네이션 누락 목록 작성
   - 실장 계정의 CRM 일괄 동기화 쓰기 권한을 실제 RLS 정책과 호출 조건을 함께 대조
   - 통계·일별 현황·카드 설명·매뉴얼의 매출 및 환자 지표 정의 대조
   - 매뉴얼 설명과 실제 화면 동작의 불일치 확인
   - CRM 브리지의 대상 origin, 세션 만료, 입원·패키지 부분 실패 처리 확인

4. **데이터 검증**
   - 데이터베이스를 읽기 전용으로 조회해 현재 행 수와 9월 매출 구성값을 재검증합니다.
   - 마스터와 실장의 읽기·쓰기 정책을 테이블별로 확인하되 데이터나 정책은 변경하지 않습니다.

## 결과 형식
다음 열을 가진 표로 보고합니다.

| 등급 | 검사 영역/화면 | 확인 결과 | 근거 | 원인·영향 | 제안 수정 |
|---|---|---|---|---|---|

- `정상`: 현재 동작과 정의가 일치
- `주의`: 현재 데이터 규모에서는 동작하지만 향후 제한 또는 수동 확인 필요
- `수정필요`: 오류, 권한 실패 가능성, 누락 집계, 잘못된 안내가 확인됨
- 문제 항목에는 정확한 파일·줄 또는 정책 근거와 최소 수정안을 적습니다.
- 실제 화면 점검이 인증 또는 내부망 제한으로 불가능한 항목은 추정하지 않고 `주의`로 명시합니다.
